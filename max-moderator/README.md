# MAX moderation bot

Бот для групповых чатов мессенджера MAX. Он удаляет сообщения по фильтрам слов и ссылок, ограничивает флуд, капс и массовые упоминания и пишет каждое действие в журнал. Правила хранятся в PostgreSQL и кэшируются в Redis. Удаления идут через очередь: не больше 2 сообщений в секунду в одном чате.

Сервис лежит в каталоге `max-moderator` и не связан с соседним приложением в корне репозитория.

## Стек

Node.js 22, TypeScript strict, `@maxhub/max-bot-api` 1.0.2, PostgreSQL, Prisma, Redis, Docker Compose, Vitest, ESLint, Prettier, pnpm.

Базовый URL API задаётся явно: `https://platform-api2.max.ru`. Токен передаётся заголовком `Authorization` и читается только из `MAX_BOT_TOKEN`.

## Возможности

- Фильтры `WORD`, `REGEX` и `SPAM_PATTERN` с действиями `DELETE`, `WARN`, `MUTE`, `KICK`, `NOTIFY_ADMINS`, `REVIEW` и уровнями `LOW` / `MEDIUM` / `HIGH` / `CRITICAL`.
- Перед сравнением текст приводится к одному виду: нижний регистр, NFKC, homoglyphs, подстановки вроде `0 → о`, повторы букв и разделители (`с*ово`, `с о в о`, `с0в0`). При `wholeWord` совпадение внутри более длинного слова не считается.
- Пользовательские regex ограничены по длине и отклоняются, если шаблон похож на ReDoS.
- Ссылки из текста, кнопок и share-вложений. Режимы `allow`, `deny`, `review`, чёрный и белый списки доменов. Бот не открывает ссылку и не скачивает её содержимое.
- Флуд, повторы, капс (по умолчанию больше 70% заглавных при длине от 20 букв) и упоминания. Для флуда ответ ступенчатый: предупреждение, удаление, запрос ограничения, уведомление администраторов.
- Не модерируются владелец, администраторы чата, `ADMIN_IDS`, роль `ADMIN` в базе и белый список.
- Повтор того же `message_id` не создаёт второе нарушение и не ставит второе удаление.
- Ошибка MAX API пишется в журнал и не останавливает обработку следующих сообщений.

`MUTE` в официальном MAX Bot API не описан. Удаление участника есть: `DELETE /chats/{chatId}/members` (`api.removeChatMember`). Для mute бот не вызывает недокументированный метод: действие фиксируется как `mute_unsupported`, сообщение при жёстком сценарии удаляется, администраторы получают просьбу решить вручную.

В групповом чате удаление чужих сообщений требует права `write` (в канале это `delete`). Право `delete` для группового чата в документации не используется.

## Команды

Доступны владельцу, администратору чата, пользователю из `ADMIN_IDS` и роли `ADMIN` в базе. `/start` и `/help` открыты всем.

- `/filter add слово` и `/filter add "плохая фраза"`
- `/filter regex "\b(spam|scam)\b"`
- `/filter list`, `/filter remove <id>`, `/filter enable <id>`, `/filter disable <id>`
- `/filter action <id> delete|warn|review|mute|kick|notify`
- `/filter severity <id> low|medium|high|critical`
- `/filter import` и список слов со следующих строк
- `/filter lexicon` — записать стартовый словарь в базу этого чата
- `/filter clear`, затем `/filter clear confirm`
- `/links mode allow|deny|review`
- `/links add <домен>` — чёрный список, `/links trust <домен>` — белый, `/links remove <домен>`, `/links list`
- `/whitelist add <userId>`, `/whitelist remove <userId>`
- `/warnings <userId>`, `/audit`, `/config`
- `/config set caps|flood|mentions|media|forwards|purge|wholeword on|off`
- `/config set hard notify|kick|mute`
- `/purge <count>` — только если очистка включена и у бота есть право удалять сообщения. Сообщения администраторов и белого списка пропускаются. Не больше 50 за вызов.

По severity, если действие само удаляет сообщение:

- `LOW` — удалить, чат не уведомлять;
- `MEDIUM` — удалить и написать предупреждение в личный диалог;
- `HIGH` — удалить и сообщить администраторам;
- `CRITICAL` — то же плюс жёсткое действие чата (`hard`, по умолчанию только уведомление).

`REVIEW` и `WARN` сами по себе сообщение не удаляют.

## Локальный запуск

```bash
cd max-moderator
cp .env.example .env
# вставьте MAX_BOT_TOKEN
corepack enable
corepack prepare pnpm@10.11.0 --activate
pnpm install
pnpm prisma generate
docker compose up -d postgres redis
pnpm prisma migrate deploy
pnpm dev
```

Postgres опубликован на `127.0.0.1:5433`, Redis на `127.0.0.1:6380`, чтобы не пересечься с другими сервисами репозитория. В `.env` для этого уже стоят `DATABASE_URL` и `REDIS_URL`.

Полный контейнер бота:

```bash
docker compose up --build
```

Проверка:

```bash
pnpm test
pnpm typecheck
pnpm lint
```

## Переменные

Смотрите `.env.example`. `MAX_BOT_TOKEN` в репозиторий не кладётся и не пишется в лог. `MAX_DELETIONS_PER_SECOND` не может быть больше 2.

## Как включить бота в MAX

1. Откройте платформу MAX для партнёров или «MAX для бизнеса» и создайте чат-бота. Скопируйте токен в `MAX_BOT_TOKEN`. В чат и в git токен не отправляйте.
2. Поднимите бота (`pnpm dev` или Docker). По умолчанию он забирает события long polling, подписка — `message_created` и `bot_added`. Для webhook задайте `BOT_MODE=webhook`, публичный `WEBHOOK_DOMAIN`, путь и `WEBHOOK_SECRET`. Библиотека проверяет секрет webhook.
3. Добавьте бота в групповой чат и назначьте администратором. Включите чтение сообщений (`read_all_messages`) и право менять сообщения (`write`): без `write` бот не удалит чужое сообщение. Для исключения участников нужно `add_remove_members`. В личном диалоге бот может удалять только свои сообщения, поэтому модерация там не удаляет чужие.
4. Напишите в чате `/start` от имени администратора. При добавлении бот создаёт настройки чата.
5. Добавьте фильтр и проверьте журнал:

```text
/filter add "куплю базу данных"
/filter action 12 delete
/filter severity 12 high
```

Номер в ответе команды будет своим, не обязательно 12. Сообщение с этой фразой от обычного участника должно исчезнуть. `/audit` покажет решение и причину без полного текста сообщения. Сообщение администратора или пользователя из `/whitelist add` останется.

6. Проверьте ссылку: `/links mode review` отправит неизвестный адрес администраторам без удаления, `/links add evil.example` удалит этот домен, `/links trust safe.example` оставит домен даже в режиме `deny`.
7. Проверьте флуд несколькими короткими сообщениями подряд. Первое срабатывание — предупреждение, дальше удаление. Капс включается на длинном сообщении из заглавных букв.
8. Если удаление вернуло 403, у бота нет права `write`. 401 — неверный токен. 404 для удаления считается уже удалённым сообщением. 429 и 5xx для удаления повторяются с паузой, отправка ответов не повторяется, чтобы не задвоить сообщение.
