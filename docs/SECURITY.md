# Безопасность

## Граница сервиса

Сервис фиксирует сообщение пользователя и объясняет, как обратиться в МВД. В нём нет функций расследования, оценки виновности, скрытого сбора данных или обещания, что сообщение будет проверено.

Признаки срочности в тексте нужны только для того, чтобы показать номера 112 и 102. Это не юридическая квалификация.

## Секреты

`BOT_TOKEN`, `CONTACT_ENCRYPTION_KEY`, пароль базы и ключи S3 задаются только переменными окружения. В репозитории есть `.env.example` с локальными заглушками. Файл `.env` не коммитится.

В `APP_ENV=production` приложение не запустится, если включён обход авторизации, выключен HTTPS, ключ шифрования пуст или в адресе базы осталась заглушка.

## Авторизация

Мини-приложение передаёт Telegram initData. Сервер проверяет HMAC-SHA256 по токену бота и срок `auth_date`. Из проверенных данных используется только числовой id. Имени профиля сервер не доверяет и не хранит его.

Заголовок `X-Dev-User-Id` работает только при `ALLOW_DEV_AUTH_BYPASS=true` и только вне production.

## Транспорт

Публичный вход в production — Nginx с TLS. При `FORCE_HTTPS=true` API отклоняет запросы без `X-Forwarded-Proto: https`, кроме проверки живости. Порт API на хосте публикуется только на `127.0.0.1`. В production его не следует открывать наружу: снаружи остаётся 443.

За Nginx нужно выставить `TRUST_PROXY=true`, чтобы ограничение частоты видело адрес клиента, а не адрес прокси.

## Ввод и файлы

- Схемы Pydantic запрещают лишние поля.
- Текст очищается от управляющих символов. Секреты и номера карт, проходящие проверку Луна, отклоняются.
- Ссылки принимаются только как http(s). Адреса localhost, частные и служебные IP, а также схемы вроде `javascript:` отклоняются. Сервер по ссылке не ходит.
- Файл проверяется по сигнатуре, размеру и опасным маркерам. Оригинальный тип от браузера не является основанием доверять файлу.
- Если задан `CLAMAV_HOST`, файл дополнительно уходит в clamd. Недоступный сканер блокирует загрузку.
- В одной карточке не больше 8 файлов.

## Роли и аудит

Роль определяется списком Telegram id: `ADMIN_TELEGRAM_IDS` и `MODERATOR_TELEGRAM_IDS`. Модератор может закрыть карточку как спам или отметить проверку полноты. Статус «обратился в МВД» ставит сам пользователь. Это не передача в полицию.

Просмотр и изменение очереди пишутся в `audit_logs`.

## Ограничение частоты

Общий лимит и отдельный лимит создания карточек считают запросы по пользователю и по IP. В production для этого нужен Redis. Если Redis недоступен, процесс переходит на память и пишет ошибку в журнал: при нескольких копиях API защита от спама тогда слабее.

## Хранение

Контакт шифруется до записи. Описание хранится как текст, потому что оно нужно владельцу карточки и для удаления спама. Диск базы и объектное хранилище должны быть у оператора с ограниченным доступом. Резервные копии нужно шифровать и удалять по тому же сроку.

Ключ Fernet генерируется так:

```bash
python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```

Потеря ключа делает сохранённые контакты нечитаемыми. Его нельзя класть в репозиторий.
