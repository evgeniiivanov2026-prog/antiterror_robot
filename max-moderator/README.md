# MAX moderation bot

Бот для групповых чатов мессенджера MAX. Он удаляет сообщения по фильтрам слов и ссылок, ограничивает флуд, капс, повторы и массовые упоминания, пишет журнал модерации и не трогает владельца, администраторов и белый список.

Стек: Node.js 22, TypeScript strict, [`@maxhub/max-bot-api`](https://dev.max.ru/docs/chatbots/bots-coding/js) 1.0.2, PostgreSQL, Prisma, Redis, Docker Compose, Vitest, ESLint, Prettier, pnpm.

## Что делает бот

- Подписывается на `message_created` и `message_edited`.
- Удаляет сообщения через `DELETE /messages`. В групповом чате бот удаляет сообщения участников, в личном диалоге — только свои, поэтому личные сообщения пользователей не модерируются.
- Все удаления идут через очередь. В одном чате не больше `MAX_DELETIONS_PER_SECOND` удалений в секунду (потолок платформы — 2).
- Запросы идут на `https://platform-api2.max.ru`. Токен передаётся заголовком `Authorization`, не в query.
- 401, 403 и 404 не повторяются. 429 и 5xx повторяются с паузой только для безопасных операций: чтение и удаление. Отправка сообщения при 5xx не повторяется.
- Правила хранятся в PostgreSQL. Активные фильтры кэшируются в Redis и сбрасываются при изменении.
- Повтор того же события не создаёт второе нарушение и не ставит удаление ещё раз.

Повторять запросы и ставить удаления в очередь нужно из-за лимита платформы: не больше двух удалений в секунду в одном чате.

## Ограничение платформы

В документации MAX Bot API нет метода временного mute. Исключение участника подтверждено: `DELETE /chats/{chatId}/members` (`api.raw.chats.removeChatMember`). Параметр `block=true` блокирует пользователя только в чате с публичной или приватной ссылкой и в остальных чатах игнорируется.

Поэтому действие `MUTE` — локальное: бот запоминает срок и удаляет следующие сообщения пользователя. Это не платформенный запрет писать. Жёсткое действие `KICK` вызывает документированный метод исключения и требует права `add_remove_members`. Удаление сообщений в групповом чате требует права `write`.

`CUSTOM_AI` включается командой `/filter ai on` и вызывает `AI_MODERATION_URL` по HTTPS. Бот не открывает ссылки из сообщений и не скачивает их содержимое. Если адрес не задан, правило ничего не делает.

У поста канала часто нет `sender`. Автомодерация работает в групповом чате (`chat_type = chat`).

## Команды

Команды, кроме `/start` и `/help`, доступны владельцу чата, администратору чата, пользователям из `ADMIN_IDS` и роли `ADMIN` во внутренней базе. Если список администраторов MAX получить не удалось, команда отклоняется. Сообщение при этом не удаляется: бот не наказывает участника, пока не уверен, что это не администратор.

`/filter add`, `/filter regex`, `/filter list`, `/filter remove`, `/filter enable`, `/filter disable`, `/filter action`, `/filter severity`, `/filter import`, `/filter clear`.

`/links mode allow|deny|review`, `/links add` (чёрный список), `/links allow` (белый список), `/links remove`.

`/whitelist`, `/warnings`, `/audit`, `/config`, `/purge`. Очистка последних сообщений выключена, пока администратор не выполнит `/config purge on`, и требует право `write`. За один раз можно удалить не больше 20 сообщений.

`/admin grant` и `/admin revoke` доступны владельцу чата и `ADMIN_IDS`.

Пример:

```text
/filter add "куплю базу данных"
/filter action 12 delete
/filter severity 12 high
```

Сообщение с этой фразой удаляется, событие попадает в `audit_logs` и `violations`. Текст сообщения в журнал не пишется: сохраняются идентификаторы, тип, причина и id правила.

Сравнение слов нормализует Unicode, регистр и визуально похожие символы, схлопывает повторы и учитывает маски вроде `с*ово`, `с о в о` и `с0в0`. Настройка `wholeWord` не даёт удалить сообщение, если запрещённое слово входит в более длинное. Regex длиннее 128 символов, с обратными ссылками или вложенными квантификаторами отклоняется.

Для флуда, капса, повторов и упоминаний ответ ступенчатый: предупреждение, затем удаление, затем локальное ограничение, затем уведомление администраторов. Неизвестная ссылка в режиме `review` не удаляется сразу.

## Запуск

```bash
cd max-moderator
cp .env.example .env
pnpm install
pnpm prisma:migrate
pnpm dev
```

Нужны PostgreSQL и Redis из `.env`. Локально их поднимает Docker Compose:

```bash
docker compose up --build
```

Пароль `maxmod` в compose только для локальной базы. В production замените его и закройте порты Postgres и Redis.

Проверка без базы:

```bash
pnpm test
pnpm typecheck
pnpm lint
```

`MAX_BOT_TOKEN` не коммитится и не пишется в логи.

## Чек-лист запуска в MAX

1. Откройте платформу MAX для партнёров: раздел чат-ботов. Если профиль верифицирован, того же бота можно создать в мини-приложении «MAX для бизнеса».
2. Создайте бота и скопируйте токен: у бота меню «⋮» → «Настройки» → копирование токена. В «MAX для бизнеса» токен также выдаёт команда «Получить токен».
3. Положите токен в `MAX_BOT_TOKEN`. В репозиторий и в логи он попадать не должен.
4. Добавьте бота в групповой чат.
5. Назначьте бота администратором. Для чтения событий включите `read_all_messages`, для удаления сообщений — `write`. Для `/purge` этого же права достаточно. Для исключения участника нужно `add_remove_members`.
6. Укажите свой числовой id в `ADMIN_IDS`, либо вызывайте команды как владелец или администратор чата.
7. Запустите бота (`pnpm dev` или `docker compose up --build`) и в чате отправьте `/help`.
8. Добавьте фильтр: `/filter add "куплю базу данных"`. Отправьте фразу с другого, не администраторского аккаунта. Сообщение должно исчезнуть.
9. Проверьте журнал: `/audit`. В нём будет действие `delete`, id пользователя и причина `word:<id>` без текста сообщения.
10. Добавьте себя в `/whitelist add <userId>` и повторите фразу: сообщение должно остаться.
11. Для ссылок задайте `/links mode review` или `/links add bad.example` и проверьте с обычного аккаунта.
12. Если бот отвечает 403 на удаление, у него нет права `write` или он не администратор. 401 означает неверный токен. 429 означает, что очередь упёрлась в лимит двух удалений в секунду: повтор делается с паузой, вручную ускорять не нужно.
