# Модератор групповых чатов MAX

Бот удаляет нежелательные сообщения в групповом чате MAX и даёт администраторам настраиваемые фильтры. Правила хранятся в PostgreSQL, активные наборы кэшируются в Redis, удаления проходят через очередь не быстрее двух сообщений в секунду на чат.

Сервис не ходит по ссылкам из сообщений и не сохраняет текст сообщения. В журнал попадают идентификаторы, тип нарушения, сработавшее правило и результат действия.

## Стек

- Node.js 22, TypeScript strict, pnpm
- `@maxhub/max-bot-api` 1.0.2
- PostgreSQL и Prisma
- Redis
- Vitest, ESLint, Prettier

## Что умеет бот

- Слова, фразы и безопасные регулярные выражения, с нормализацией Unicode, гомоглифов, leet-подмен и вставок вроде `с*лово`.
- Ссылки: белый и чёрный списки, режимы `allow`, `deny` и `review`, punycode, IP-литералы и короткие ссылки. Содержимое URL не загружается.
- Флуд, капс, повторы и массовые упоминания со ступенчатой реакцией: предупреждение, удаление, мягкое ограничение, уведомление администраторов.
- Команды администратора, белый список, журнал `/audit`.
- Повторное событие с тем же ключом не создаёт второе нарушение и не ставит сообщение в очередь удаления повторно.

Сообщения владельца, администраторов чата, пользователей из `ADMIN_IDS`, роли `ADMIN`/`OWNER` во внутренней базе и белого списка не модерируются.

## Запуск

Пошаговая инструкция без лишних терминов: [КАК-ЗАПУСТИТЬ.md](КАК-ЗАПУСТИТЬ.md).

```bash
cd max-moderator
cp .env.example .env
# впишите MAX_BOT_TOKEN
bash up.sh
```

Postgres на хосте доступен на порту `5433`, Redis — на `6380`, чтобы не пересечься с другими локальными сервисами. Внутри сети Compose бот сам подключается к `postgres` и `redis`.

Без Docker, когда базы уже запущены:

```bash
pnpm install
pnpm exec prisma generate
pnpm exec prisma migrate deploy
pnpm dev
```

Проверка:

```bash
pnpm test
pnpm typecheck
pnpm lint
```

По умолчанию бот забирает обновления через long polling. Для production задайте `BOT_MODE=webhook`, публичный `WEBHOOK_DOMAIN`, `WEBHOOK_PATH` и длинный `WEBHOOK_SECRET`. Библиотека поднимет HTTP-сервер и зарегистрирует подписку. Документация MAX считает long polling режимом для разработки.

## Команды

`/start` и `/help` отвечают в чате всем. Остальные команды выполняются только владельцем, администратором чата, пользователем из `ADMIN_IDS` или ролью `ADMIN`/`OWNER` в базе.

```text
/config
/filter add слово
/filter add "плохая фраза"
/filter regex "\b(spam|scam)\b"
/filter action 12 delete
/filter severity 12 high
/filter list
/filter remove 12
/filter enable 12
/filter disable 12
/filter import
/filter clear
/filter clear confirm
/links mode allow|deny|review
/links add example.com
/links add trusted.example allow
/links remove example.com
/whitelist add 123
/whitelist remove 123
/warnings 123
/audit
/purge 10
```

`/purge` работает только после `/config purge on` и только если у бота есть право удалять сообщения. Дополнительные переключатели: `/config enabled`, `/config spam`, `/config caps`, `/config hard-action none|mute|kick`, `/config flood <сообщений> <секунд>`.

Важность по умолчанию для нового фильтра — `LOW`: сообщение удаляется без уведомления чата. `MEDIUM` добавляет личное предупреждение, `HIGH` — уведомление администраторов, `CRITICAL` — ещё и жёсткое действие из `/config hard-action`. Подозрительные правила можно сразу ставить в `review`: такое сообщение не удаляется, а уходит администраторам.

`/filter import` принимает строки в том же сообщении или следующим сообщением. Строки, начинающиеся с `#`, пропускаются.

## Как устроено удаление

Официальный клиент 1.0.2 не содержит метод `api.raw.delete(path, options)` из раннего руководства. Удаление идёт через `api.raw.messages.delete({ message_id })`: это `DELETE /messages?message_id=` на `https://platform-api2.max.ru` с заголовком `Authorization`. Токен в query не передаётся.

Исключение участника — `DELETE /chats/{chatId}/members` (`api.raw.chats.removeChatMember`). Параметр `block` по умолчанию не включается.

Отдельного метода «заглушить пользователя» в документации MAX нет. `MUTE` записывает срок в Redis и удаляет следующие сообщения пользователя, пока срок не истечёт. Это ограничение нужно проверить на вашей версии клиента MAX: API может появиться позже.

Ошибки `429` и `5xx` повторяются с паузой. `401`, `403` и логическая ошибка в теле ответа не повторяются. `404` при удалении считается уже выполненным удалением. Ошибка API не останавливает обработку следующих сообщений и всё равно попадает в журнал.

Команда `/filter ai review` включает опциональную проверку спорных сообщений. Она вызывается, только если остальные фильтры ничего не нашли и задан `AI_MODERATION_URL`. Запрос содержит только текст, обрывается через 1,5 секунды и при сбое не влияет на остальные фильтры. Результат — `review` или уведомление администраторов, без немедленного удаления.

## Данные

Таблицы: `chat_settings`, `word_filters`, `link_rules`, `user_whitelist`, `violations`, `audit_logs`, `admin_roles`, `processed_events`.

Индексы: уникальный `chat_settings(chat_id)`, `word_filters(chat_id, enabled)`, `violations(chat_id, user_id, created_at)`, `audit_logs(chat_id, created_at)`. Повтор нарушения по одному сообщению закрыт уникальной парой `chat_id + message_id`.

## Чек-лист запуска в MAX

1. Откройте платформу MAX для партнёров или мини-приложение «MAX для бизнеса» и создайте бота. Токен лежит в разделе чат-ботов: меню бота → настройки → копирование. Документация: [dev.max.ru](https://dev.max.ru/docs/chatbots/bots-coding/js).
2. Положите токен в `MAX_BOT_TOKEN`. Не коммитьте `.env` и не пишите токен в логи. В репозитории есть только `.env.example`.
3. Если платформа требует сертификат Минцифры для `platform-api2.max.ru`, добавьте его в доверенные сертификаты окружения, где запущен бот.
4. Поднимите Postgres, Redis и бота: `bash up.sh` из каталога `max-moderator`.
5. Добавьте бота в групповой чат и назначьте администратором. Для чтения чужих сообщений нужно право `read_all_messages`. Для удаления — `write` (в канале это право `delete`). Для `/purge` и исключения участников дополнительно нужно `add_remove_members` на команду исключения.
6. В чате отправьте `/start`. Затем от имени администратора:

   ```text
   /filter add "куплю базу данных"
   /filter action 1 delete
   /filter severity 1 high
   ```

   Номер в `/filter action` возьмите из ответа `/filter list`, если он отличается от 1.
7. С обычного аккаунта, которого нет в белом списке и среди администраторов, отправьте фразу `куплю базу данных`. Бот удалит сообщение не быстрее лимита чата и запишет событие.
8. Проверьте `/audit`: в журнале есть действие `delete`, идентификатор пользователя, тип `WORD` и номер правила. Текста сообщения там нет.
9. Добавьте себя в белый список (`/whitelist add <userId>`) и отправьте ту же фразу: сообщение останется.
10. Проверьте ссылку: `/links add evil.example`, затем сообщение с `https://evil.example`. В режиме `review` неизвестные домены не удаляются, а уходят администраторам; домен из чёрного списка удаляется.
11. Для флуда отправьте больше 5 разных коротких сообщений за 10 секунд. Первое срабатывание — предупреждение, следующие ступени удаляют сообщение и могут включить мягкое ограничение.
12. Убедитесь, что сообщение администратора с запрещённым словом не удаляется.

Если удаление отвечает `403`, у бота нет права `write` или это личный диалог: в диалоге бот может удалять только свои сообщения, поэтому чужие сообщения там не модерируются.
